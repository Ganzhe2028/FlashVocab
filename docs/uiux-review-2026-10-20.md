# 闪词 UIUX 评审（2026-10-20）

> 评审对象：P0–P2 交付后的本地生产构建，暗色与亮色、桌面与 390px 移动视口都过了一遍。本文是后续视觉与交互改造的底稿，改造人：Hermes。已按仓库规则跑过 ui-ux-pro-max 搜索，命中为通用条目，以下结论以其实证截图和优先级表（Accessibility > Touch > Feedback > Layout > Typography）为据。

## 总体判断

骨架是好的。编辑部式的安静阅读版面没有被打扰，三档判断的按钮层级清楚，记忆画面卡、对位引用块、结算页统计行这些新内容都顺着原有的纸面语言长出来了，浅色暗色都成立，移动端没有横向滚动和挤压。问题集中在四处：结算页的按钮群、答题反馈的标记完整性、几处文案的语气与术语泄漏、若干组件级的视觉密度。

## 问题清单

### A 级（影响理解与操作，先改）

<a id="a1"></a>

**A1. 结算页按钮群层级塌陷**
六个按钮（继续下一轮 / 回准备页 / 练习选择题 / 练习情景题 / 练习词库题 / 练习对位辨析）同一行排不下就自然换行，「练习对位辨析」孤零零掉到第二行。主行动（继续下一轮）和四个平级练习入口、一个导航出口混在一起。
改法：拆两层。第一层只放主行动「继续下一轮 Enter」和次行动「回准备页」；第二层加一个小标题「练一练」统率四个题型按钮，2×2 网格，换行整齐。题型按钮补一句五字内的副标（选择题=释义选词，情景题=情景选词，词库题=搭配选词，对位=近义辨析），降低第一次见的理解成本。

<a id="a2"></a>

**A2. 答错时不标记用户选的是哪个**
MCQ 答错后只有正确项变青绿，其余选项统一变暗。用户选错的那个没有任何标记，得自己回忆刚才按了几。反馈不完整——对错的对照恰恰是这一屏的学习价值。
改法：用户选错项加珊瑚红描边或底纹，正确项保持青绿，未选项变暗。三色分工：红=你选的错项，绿=正确答案，灰=无关项。

<a id="a3"></a>

**A3. Undo 提示双份**
操作后 header 常驻 Undo 按钮和悬浮 toast（文案完全一样，如「撤销恢复示例」）同时出现，一个动作两处回声。
改法：toast 保留 5 秒自动消失，header 的 Undo 按钮在 toast 存活期间隐藏，toast 消失后按钮出现。两个时段只留一个入口。

### B 级（语气与一致性，跟着改）

<a id="b4"></a>

**B4. 首次进入的 toast 文案语境错位**
点「用示例词体验」后弹「已换成 24 个词」。第一次来的用户没换过任何东西。这句文案是为「替换已有词表」写的，首次进入时读会愣一下。
改法：区分场景。首次载入示例：「已装入 24 个示例词。」；替换已有词表：「已换成 N 个词。」

<a id="b5"></a>

**B5. 对位辨析缺料提示泄漏字段名**
提示写「请先导入或补齐 miniScenario / contrastScenarios」。字段名直接出现在用户文案里，同学看了会懵。
改法：改成「对位辨析需要 AI 备料生成的分界线情景。在词表面板用 DeepSeek 补齐，或导入含备料数据的词表。」字段名收进括号小字或开发者注释。

<a id="b6"></a>

**B6. 词库题额外词大小写不统一**
词库里 deck 词是 Title Case（Devise），relatedWord 来的额外词是小写（improvise、glance、struggling），混排扎眼。
改法：词库按钮统一 Title Case 展示，判分时按原字段值比对。

<a id="b7"></a>

**B7. 初见局提示的语气**
「初见局：可用情景题不足，先从辨识学词；补上例句后可练情景题。」是好提示，青绿色让它像成功状态。
改法：这类「降级说明」用次级文字色（muted），不用强调色。强调色留给可操作的积极信息。

### C 级（打磨，最后做）

<a id="c8"></a>

**C8. 记忆画面卡的视觉密度**
当前是两个图标加箭头加一行图注，信息对但单薄，在 E 的二十秒里撑不起「主锚点」的视觉地位。
改法：图注放大半级，图标区上下留白加 8px，整张卡加左侧 2px 强调色边条，和其他内容卡区分开。结构不动，只调呼吸和分量。

<a id="c9"></a>

**C9. Q 的两键前进**
认识的词要按 Q 再按 N 才走，fast path 是两拍。
改法：保持现状作为默认（防误触），设置里加一个「认识的词直接前进」开关，开了以后 Q 即 N。高频用户自己选。

<a id="c10"></a>

**C10. 词库题数字键超 9 的映射**
词库 24+3 个按钮标了数字，10 以后按什么没有说明。
改法：词库题只给前 9 个位置数字键帽，其余纯点击；或在说明行写清「点击选择」。需要先在代码里确认现状再定。

<a id="c11"></a>

**C11. 空字段的留白**
「词性未提供」一行小字孤零零挂在单词下面，像出错了。
改法：缺字段时不渲染该行，让单词和发音按钮独占视觉中心；或者改成更中性的灰度小字「无词性资料」。

## 改造顺序

[A1](#a1) → [A2](#a2) → [A3](#a3) 先行（一屏之内见效），B 级跟随，C 级打磨。每改一项跑 `npm run check`，UI 行为测试同步更新。视觉验证用真实浏览器截图对照本文。

<a id="codex-uiux-record"></a>

## Codex 落实记录

- [A1](#a1)：结算操作分层，四类练习改为 2×2 网格；短说明与按钮的无障碍描述关联，原快捷键与练习入口保留。

- [A2](#a2)：错误选项加珊瑚红与「你的选择（错）」文字，正确项保留青绿和文字标记，其他项淡化；测试覆盖答对、答错与单次提交。

- [A3](#a3)：Undo 前五秒只在 toast，之后只在顶部；空状态不再重复放入口。键盘焦点随到期提示转移，测试覆盖 4999/5000ms 边界和空状态；真实窄屏发现并修复旧媒体查询隐藏 Undo 的遗漏，顶部改为换行。

- [B4](#b4)：首次示例写「已装入」，已有词库写「已换成」；toast 和侧栏共用同一条消息。两种路径均有 UI 测试。

- [B5](#b5)：对位缺料提示只说需要什么、去哪补，不向学习者暴露字段名；测试确认资料不足时保留原学习现场。

- [B6](#b6)：词库按钮统一 Title Case；不改原数据、ID 或判分值，测试用小写目标词确认仍可答对且保存值不变。

- [B7](#b7)：初见局降级说明独立为 muted 学习提示，不被导入成功覆盖；首次判断或成功进入题组后收起。

- [C8](#c8)：记忆图结构不变，增加 2px 左边条、图形上下各 8px 空间，图注放大到 1.0625rem；已用真实浏览器核对亮色和 375px 暗色，见下方截图。

- [C9](#c9)：新增默认关闭的直接前进开关；Q 复用原评分与队列路径，W/E 不变。学习页和帮助同步说明；下一词仍在 Q 事件内同步发音，逻辑与 UI 测试覆盖。

- [C10](#c10)：代码原本就只给前九项数字键帽；补齐点击、Tab/Enter 说明。12 词 UI 测试确认第十项无数字键帽、0 不误选、点击仍可作答。

- [C11](#c11)：缺词性不显示占位，词性与注音都缺时省掉整行；已有注音独立保留，两种资料组合均有 UI 测试。
