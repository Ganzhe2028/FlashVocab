# 闪词导入优先改版（2026-10-27）

> 2026-10-29 更新：导入现已固定为纯 JSON 数组，旧多格式识别和竖线/标签回复均不再进入词库。文件、粘贴、AI 补全和转换统一校验，提供模板下载；具体契约见 [技术文档](TECHNICAL.md#6-导入管线)。下文旧格式说明保留为历史记录。

## 为什么改

真实用户反馈集中在三件事：

1. 第一次打开不知道闪词到底怎么用。
2. 自己输入「英文 + 中文」却被判为无法识别。
3. 老师发的 Word 单词表，要经过「复制闪词里的提示词 → 发给 DeepSeek → 让它返回 JSON → 再复制回闪词」这一串步骤，实际上无法完成。

旧版并不是缺说明，而是把关键动作藏进了「更多 → 怎么用」：导入、AI、JSON、波次、辨识、备考全挤在文字说明里，用户仍然不知道下一步该点哪里。这次按「交互优先于文字指引」重做，不靠再加一段说明来弥补流程本身。

## 现在的首次使用

这一版在 2026-10-27 又按真实新用户的阅读顺序收了一次：第一版把文件、粘贴、补全、命名、词表入口都放在同一屏，用户虽然能完成，但不知道先看哪里、现在进行到哪一步。现在改成三步向导，每一步只保留一个决定和一个主动作。

### 三步向导

`1 放入 → 2 核对 → 3 开始`

- 每一步顶部都有这个进度指示；已完成的一步显示对勾，当前步高亮，下一步保持灰色。
- 页面切换时焦点移到新标题，键盘和读屏用户不会留在上一步的输入框里。
- 首次打开时顶部只留「闪词」品牌，隐藏设置、帮助、GitHub 和词表入口，避免在还没开始前先看到一排全局按钮。

### 第 1 步：放入

- 只有一个问题：「单词表在哪？」
- 来源只有两个 tab：「文件」「粘贴」。切到哪个，下面才出现哪个操作，不再同时摆两张卡。
- 文件模式只有一个上传目标：点击选择或拖入。支持 Word、Excel、CSV、TXT、Markdown、JSON；旧 `.doc` / `.xls` 会提示另存为。
- 文件读取期间，上传区显示「正在识别…」，用户知道网站正在处理。
- 粘贴模式只有一行提示、一个输入框和一个「识别单词」。占位文字直接示范 `abandon 放弃`，不再另写一段格式说明。
- 首次访问才显示「没有词表？用 24 个示例词试试」；已有词表时不显示。
- 页面底部只保留一行「只保存在这台设备」。没有命名、没有 AI 设置、没有长格式说明、没有第二个上传入口；格式只用一行「Word · Excel · CSV · 文本」带过。

### 第 2 步：核对

这一屏只回答一个问题：「这些词对吗？」

- 一行摘要：「5 个词 · 4 个有中文释义」。
- 词缺资料时只多一行：「1 个词还没补全资料 · 让 AI 补全」。点开才出现 AI 补全面板；补全是可选项，不补也能直接开始背。
- 前 5 个词按「单词 / 中文」两列显示；超过 5 个时才出现「展开全部 N 个」。
- 没识别的行收在「N 行没识别」的折叠项里，说明「像完整句子」或「没有单词」。
- 有旧词表时补一句「会加进「词表」，原来的不会丢」。
- 整屏只有一个主按钮：「开始背这 N 个词」。返回是左上角的「← 换一份」文字链接，不再放第二个同权重按钮。
- 导入阶段不命名。默认使用 W1、W2；导入后可在「词表」面板对每一组词点「改名」，不占核对步骤的注意力。

### 第 3 步：开始

点「开始背这 N 个词」直接进入认词，不再多一次确认页。进度条里的「开始」就是这一步；学习页本身是第 3 步的落地。

### 学习中途再加一组

学习页进入导入时，左上角出现「← 继续学习」。它与三步向导不冲突，不导入时可以原样返回；新增词表后按 Undo 也会回到原来的学习现场，而不是停在导入页。

## 匹配/填空 worksheet：不再假装能解析

真实的 HTA Chapter 4 worksheet 暴露了一个比解析 bug 更根本的问题：它不是「一行一个词」的词表，而是两份表——

- 一张词库表，每行放 5 个词，词后带页码，如 `unequivocally (54)`；
- 一张释义匹配表，`Vocabulary` 列是空的，只有编号、页码、词性和英文释义。

学生版没有答案，单词和释义的对应关系只存在于题目设计里；本地解析器无法可靠地猜出「哪个释义配哪个词」。旧逻辑会把词库行里的第二个词误当成第一个词的释义，预览看起来像成功了，实际词义是错的。

现在的处理：

- 解析后先做一次低置信度检查：单词或释义里出现 `(54)` 这种页码、或把长释义误识别成单词时，不再展示「这些词对吗」的假预览。
- 第 2 步直接切换为「这份表要请 AI 读一下。」，说明「单词和释义分开放，闪词猜不出谁配谁」。
- 面板里给三步，顺序按真实操作而不是按信息完整性：
  1. 先复制给 AI 的话（不用先读完全部说明）；
  2. 打开 DeepSeek，把原文件和刚复制的话一起发送；
  3. 把 AI 的回复粘贴回来。
- 提示词要求 AI 先把单词和释义配好，再按和导入补全相同的完整字段输出每个词（释义、词源、对应词、原形例句与重点、情景、辨析），不要求 JSON；旧的 `单词 | 词性 | 中文释义 | 英文释义` 竖线回复仍然接受。
- 收到回复后替换掉不可用的预览，进入正常的「这些词对吗」核对；这时才开始计词数、缺资料和背诵，词表也直接带齐四项专项练习需要的资料。
- 文件完全读不出来（例如 PDF、旧格式或损坏文件）时，错误下面也会出现「把这份文件交给 AI 整理」，走同一个面板。

这不是把解析器做得更复杂，而是承认这类 worksheet 的正确工具是能同时看词库和释义表的 AI；闪词负责把交接说清楚，并把结果接回来。

## 解析契约

`src/utils/deckImport.js` 先尝试 JSON / Markdown / 带表头的 CSV，再进入宽松文本解析，最后才报错。宽松解析支持：

- `abandon 放弃`
- `1. abandon v. 放弃`
- `abandon /əˈbændən/ v. 放弃；抛弃`
- `abandon (v.) 放弃`
- `take off 起飞`、`look after 照顾`
- `abandon\tv.\t放弃\tto leave somebody`
- `abandon | v. | 放弃 | to leave`
- 无表头 CSV：`abandon,放弃`
- Word 表格：整行按 `单词 / 词性 / 中文 / 例句` 读取；短例句也能进入例句数组
- 英文、中文分行的成对数据：`abandon` 下一行 `放弃`
- 中文在前的行：`放弃 abandon`
- 方括号词条：`[abandon] 放弃`

解析会跳过 `Unit 1 Vocabulary`、`单词 词性 中文`、页码、姓名日期等标题行。无法识别的完整句子不会被硬塞成单词。仍无法识别时，错误消息会指出第一行内容，并给出 `abandon 放弃` 的格式示例。

Word 的表格提取在 `extractDocxText` 内完成：表格每一行转换为 tab 分隔的一行，避免单元格被拆散；普通段落保持逐行文本。Excel 用原生 ZIP + `sharedStrings.xml` + 第一个有内容的 `sheet*.xml` 读取，不新增运行时依赖。

## 英文释义和例句的归类

AI 回复的 `英文释义` 经常是多词短语，比如 `treating a holy thing or place without respect`，没有句号、首字母小写。旧解析把它当成了「例句」，结果学习卡上中文释义在、英文释义却显示「未提供释义」，下面还多出一句假例句。

现在按单元格内容区分：

- 只有「首字母大写、并且以 `.` / `?` / `!` / `。` / `？` / `！` 结尾」的英文单元格才进 `examples`；
- 其余英文定义进 `meaning`；
- 加载旧词表时，如果 `meaning` 为空、只有一个无 focus 的小写定义例句，会自动把它移回 `meaning`，不需要重新导入。

## 导入时一次补齐学习卡和专项练习资料

早先的补全只补中文释义。四项专项练习要的例句、情景和辨析材料，得等导入完再打开「词表 → 用 DeepSeek 补全资料（进阶）」走一次 API。现在复制给 AI 的那段话当场带齐练习需要的东西，导入完就能直接练。

### 触发

核对页只要有词缺资料——中文释义、英文释义、能出题的例句、对应词或辨析材料——就多出一行「`N` 个词还没补全资料」和一个「让 AI 补全」按钮。这是次级入口，主按钮仍是「开始背这 N 个词」；补全可选，不点也能直接导入。

### 面板与提示词

展开后的标题是「让 AI 一次补齐」，说明这段提示词会补中文释义、词性、英文释义、词源、对应词、例句和辨析情景，已有内容不会被覆盖。操作仍是三步：

1. 复制生成好的提示词；
2. 发给 DeepSeek、ChatGPT 或任意 AI；
3. 把 AI 的回复整段粘回来，点「识别并补全」。

提示词是普通文字，不是 JSON，也没有 Markdown 表格和编号。它只列出缺资料的词；已有对应词的会写成 `abandon（已有对应词：quit，请沿用）`，并要求辨析答案沿用这个词，合并后仍落在原来那一对词上。词与词之间空一行，每个词包含：

- `单词 | 词性 | 中文释义 | 英文释义`
- `词源: ...`：1–2 句中文，写可靠的词根和词源；拿不准的记忆法要标明。
- `对应词: English counterpart — 中文区别说明`
- `例句1: ...` / `重点1: ...`、`例句2: ...` / `重点2: ...`：句子必须包含原形单词，不写 -ed / -ing / -s 变形；重点是句中包含原形词的连续片段。
- `情景: ...`：目标词用得上的英文日常情景，不能出现目标词或对应词。
- `辨析: 对应词一侧的情景 | 对应词 | 中文分界说明`

第一行的第一个字段只写单词本身，不带括号里的对应词提示和 -ed / -ing / -s 变形；编号和列表符号会被忽略。

### 合并与校验

`mergeFilledEntries` 的规则：

- 按单词匹配，大小写不敏感；只填缺失字段，已有的释义、例句、词源、对应词、情景和辨析数据一律不覆盖。
- 除了提示词要求的竖线首行，英文标签回复（`Word:` / `Term:` / `单词:` / `词条:` 起头）和 `[term]` / `【term】` 块头也能解析；旧的竖线行、Markdown 表格和 JSON 回复继续接受。
- 例句只有在句子里出现原形单词、且重点能在句中验证时才接受。
- 情景提到目标词或对应词会被拒绝——那等于把答案写在题面上。
- 辨析的答案必须属于目标词和它的对应词；只有一条合格的迷你情景时，会把它复用为目标词一侧的辨析情景。
- 回复里出现 `POS:`、`Meaning (ZH):`、`Word Origin:`、`Counterpart:`、`Focus 1:` 这类字段标签，却没有任何可识别的词条起头时，按格式错误处理：导入补全不写入任何内容，worksheet 路径提示「没有在回复里找到词表。请让 AI 按提示里的格式重新输出。」，不替换预览。
- 结果里 `filled` 是实际改动的词数，`remaining` 是仍缺资料的词数。

### 部分回复

AI 回复被截断、或只补了一部分，可以直接粘贴：缺的词先补上，提示「补全了 N 个词；还有 M 个词没补完，可以再复制一次。」，面板保持打开，再复制一次就只列剩下的词。全部补齐后面板收起，提示「补全了 N 个词的资料，专项练习可以用了。」。没有匹配到任何词时直接说明，不会悄悄改词表。

### worksheet 路径

匹配/填空 worksheet 的救援提示词同步扩展：AI 先完成配对，再按同样的完整字段输出每个词。一段回复就能替掉原本不可用的预览，得到能直接出题的资料；旧的竖线词表回复仍然接受。

### 结果

导入后常见的词表已经具备四项专项练习的材料——看释义选词、看情景选词、填搭配、辨析近义词——不需要 API key，也不用再走进阶补全。练习入口缺资料时的提示也指向这个补全入口；辨析近义词的提示仍保留原来的词表进阶路径。补齐只在用户点击后发生：导入本身不自动调用 AI、不联网等待。AI 回复的质量和长度取决于用户用的 AI 和这段提示词，很长的词表可能一次回不完，复制两遍即可；整个过程不需要懂 JSON。

## 设置页

旧设置页的问题是：开关、说明、拼写单选和外观混在一列里，用户得先理解「辨识字直接前进」「休整」这些概念，才能知道自己在选什么。现在：

- 第一块「练习方式」用三张结果导向的选择卡：
  - 纯刷词
  - 刷词+拼写错词
  - 刷词+拼写全部
- 每张卡只说明会发生什么，不再解释内部轮次。
- 「发音」独立成一块，使用真正的 toggle，并只保留一条行为说明。
- 「外观」保持三段选择。
- 「认识的词直接前进」折叠进「进阶」，默认关闭。
- 重置进度和恢复示例词回到「词表 → 重新开始」，不再混在设置里。

## 学习流程

- 任何新词表都从认词开始，不会再因为词表恰好带例句就直接进入情景题。情景题、填搭配、辨析近义词只在结算页或「词表 → 专项练习」出现。
- 认词页只有 Q 认识 / E 不认识、N 下一个；答案页才出现 M 改判。首次使用的提示卡被移除，按钮本身已经写明操作。
- 结算页的练习名称改为「看释义选词 / 看情景选词 / 填搭配 / 辨析近义词」，并在按钮下给一句短说明。
- 词表管理里的用户词改为「在学 / 已收起」「练这组 / 先收起 / 全部一起复习」，不再暴露「冷藏」「复活」「波次」这些内部说法。

## 明确移除

- 「更多 → 怎么用 → 1 分钟上手」的完整文字教程。
- 认词和拼写页的首次提示卡，以及「在学习页重新显示提示」。
- 导入时等待 DeepSeek、用 API key 作为导入前置条件的路径。
- 面向学习者的 JSON 补全提示词。
- 顶部 `准备页`、`Import`、`更多` 三入口和面板二级 tab。
- 新词表自动进入情景题的「初见局」。
- 第 1 步同时并排的文件卡 / 粘贴卡 / 命名 / 查看已有词表。
- 第 2 步的字段胶囊、词性/例句统计、命名折叠和「调整原文」次按钮。

## 已知边界

- 旧 `.doc` 仍需另存为 `.docx`，旧 `.xls` 需另存为 `.xlsx` 或 CSV；PDF、图片和扫描件不支持，避免用不可靠 OCR 误导用户。
- AI 补全依赖用户自己打开的第三方 AI；闪词只负责生成可复制的普通文字和合并回复。导入时的补全已经覆盖四项专项练习需要的资料；DeepSeek API 补全仍在「词表 → 进阶」内，属于可选进阶，需要自己的 key。
- AI 回复的质量和长度取决于用户用的 AI 与这段提示词；很长的词表可能一次回不完，复制两遍补齐剩余词即可，不需要懂 JSON。
- AI 偶尔会换个回复格式：英文标签、`[term]` 块头和旧的竖线/表格/JSON 都能接。只有字段标签、没有词条起头的回复会被拒绝，不会把 `POS`、`Meaning (ZH)` 这类标签写成单词。
- 补全只在用户主动点击后发生：导入本身不自动调用 AI、不联网等待，也不需要 key。
- Excel 只读取第一个有内容的工作表；多工作表需要拆成多个文件或复制到同一张表。
- 没有中文释义的词仍可导入，但认词答案会是空的；预览会明确提示，也可以用「让 AI 一次补齐」在导入时补上。
