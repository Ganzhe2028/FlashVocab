# Codex Goal 速用：闪词重设计（2026-10-19）

给 Codex（codex-cli 0.160.1，model = gpt-6.1-sol，`features.goals = true` 已开）设置 goal 来执行重设计的重开发环节。本文件自包含，照做即可。

## 用法

1. `cd ~/dev/vocab2 && codex`
2. 会话起来后，把「主目标」那一整段贴进去（以 `/goal` 开头）
3. 若 TUI 追问 token budget：主目标填 `800000`，备选小目标填 `300000`。没追问就走默认预算；想事后补设，用 App Server API：`thread/goal/set`，params 带 `objective` 和 `token_budget`
4. 生命周期管理：`/goal` 单发查看状态，`/goal pause` 暂停（离开电脑前建议先暂停），`/goal resume` 继续，`/goal edit` 修改，`/goal clear` 清除
5. 硬性上限（可选）：`~/.codex/config.toml` 加 `[goals]` 一行 `max_goal_token_budget = 1000000`

## 主目标（P0–P2 全量，推荐）

```text
/goal 按 docs/flashvocab-redesign-2026-10-19.md 落地 P0、P1、P2 的全部条目，让重设计规格成为现实。verified by：npm run check 全绿（eslint + node --test + vitest + vite build），P0–P2 每一条都有新增或更新的行为测试，文档与最终实现保持同步（遵循 AGENTS.md 的 MUST DO 规则）。while preserving：现有学习契约不回退——辨识与拼写循环、dueRound 休整机制、Undo 槽、导入导出字段兼容、内置 24 词示例词表行为、发音契约（学习动作内同步触发、不在 React cleanup 里调 speechSynthesis.cancel）；不新增运行时依赖，确有必要就在交付说明里写明理由；dist/ 只通过 npm run build 重新生成。Use：只动本仓库的文件；规格的唯一来源是 docs/flashvocab-redesign-2026-10-19.md 加 AGENTS.md；docs/ 下的历史文档可以参考，2.x 已移除的行为不得恢复。Between iterations：一次只做一个 P 条目，顺序 P0 到 P1 到 P2；每条做完立刻跑 npm run check，红了先修再继续；取最小可验证改动，不做规格之外的重构。If blocked：停下来汇报——卡在哪一步、试过什么、缺什么输入（设计决策、API key、外部账号），以及哪个选择能解锁；不许跳过验证就宣告完成。
```

## 备选小目标（只想先动 P0 修缺陷加 P1 三件套）

```text
/goal 按 docs/flashvocab-redesign-2026-10-19.md 落地 P0（必修缺陷清单）与 P1（MCQ 现场组卷、掌握度排序、轮次结算页）。verified by：npm run check 全绿，P0 五条与 P1 三件各有新增或更新的行为测试，文档同步更新。while preserving：同主目标的约束清单。Use：只动本仓库；规格唯一来源是该文档加 AGENTS.md。Between iterations：一次一个条目，做完立刻 npm run check，红了先修；最小可验证改动。If blocked：停下汇报卡点、已尝试路径、缺的输入和解锁选项；不许跳过验证宣告完成。
```

## 行为备注（与官方文档核对过）

- goal 是 thread 级持久状态，目标文本同时充当起始提示词和完成标准
- 只有线程空闲、目标 active、预算未耗尽时才自动续跑；某次续跑一个工具都没调用，下一次自动续跑会被抑制，防空转
- 预算耗尽是软停：当前回合体面收尾，总结进展、阻塞项和下一步；`/goal resume` 接着来，累计进度保留
- 完成必须由模型对照证据审计（改过的文件、跑过的测试、构建产物），不是它觉得完了就算完
- 官方说明页：https://developers.openai.com/cookbook/examples/codex/using_goals_in_codex
