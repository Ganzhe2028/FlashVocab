## 结论

闪词 3.0 不是一次“距离上次改版够久了”的视觉翻新，而是一次职责重构。

**闪词 3.0 是一款面向临近课堂词汇 quiz 的、键盘优先的个人词表冲刺网页。**它把老师临时给出的非标准小词表，快速变成可在本地保存、反复使用的练习回路：先低摩擦辨识，再把已经具备基础的词自动送入拼写验证；释义优先帮助用户建立英语与概念之间的直接联系，深层理解工具只在卡住时出现。

它替用户外包的是：词表整理、轮转、筛选、阶段衔接和恢复。它不替用户建立一整套长期英语课程。

3.0 的核心变化不是增加功能，而是让系统承担原本由用户承担的三类工作：

1. 决定此刻应该继续辨识，还是进入拼写；
2. 隐藏当前任务不需要的界面和解释；
3. 清楚说明“为什么没有词出现、接下来会发生什么”。

## 一、从人群到产品的完整链条

### 1. 目标人群

主用户不是泛指“所有学英语的人”，而是以下条件的交集：

- 中文语境下的学生；
- 老师不定期给出 Word、表格或其他非标准格式的临时词表；
- 数天内有 quiz、期中或期末抽查；
- 每次通常有 10–15 分钟碎片时间；
- 主要在电脑上学习，愿意依赖键盘；
- 结果要求以写对拼写、辨认词性和理解核心含义为主。

其他自定义词表学习者可以使用，但不应反过来把产品推向通用背词 App。

### 2. 核心场景

用户收到一份几十个词的临时词表。它不在成熟背词 App 的现成词库中，又很快要考。用户需要在当天或接下来几天里，多次利用碎片时间快速过词，并在熟悉后检查自己能否拼写。

### 3. 痛点

痛点是现有方法造成的阻力，不是产品功能的反向描述：

- 纸笔需要抄写、遮挡、翻找和携带；
- 成熟背词 App 对临时词表的导入、修改和再次导入太重；
- 再次学习同一词表时，准备工作容易重复；
- 学习过程中频繁读提示、找按钮和选择分支，会打断记忆节奏；
- 系统隐藏或跳过单词时缺少解释，容易被误认为 bug。

### 4. 需求

- 在短时间内大量、重复地过一份自定义词表；
- 随时中断，下次打开能继续；
- 先建立辨识，再验证拼写；
- 词表能快速导入、即时替换或补充，并能保存副本；
- 优先通过足够简单的英英释义理解单词，并保留中文作为快速定位和校准；
- 卡住时可获得发音、例句、词源和画面理解帮助；
- 不需要账户、复杂设置或原生 App。

### 5. Job to be done

> 当我收到一份临时词表并很快要测验时，帮我在极少准备、无需账户和复杂设置的前提下，把它保存成自己的练习材料；每次打开立刻从上次进度继续，用键盘高频辨识，并只在已经具备基础时进入拼写，让我能在测验中写对词、词性和核心意思。

## 二、产品原则

### 1. 少、轻、快、好理解

每一步都要接受四个问题：

- 是否减少了开始学习前的准备？
- 是否减少了学习中的决策或操作？
- 是否直接提高本次 quiz 所需的辨识或拼写？
- 是否让下次使用更容易？

四项都不满足的功能，不进入主界面。

### 2. 键盘优先，界面退后

连续学习时，默认动作应尽量由同一个键完成。鼠标和触摸入口仍需可发现，但不持续争夺注意力。

### 3. 系统给出默认路线，用户保留改选权

系统根据学习证据决定下一阶段；用户不必每轮停下来判断，但仍可通过一个次级动作覆盖系统建议。

### 4. 渐进显露

- 主层：当前必须记住或输入的内容；
- 辅层：词性、音标、当前小进度；
- 理解层：例句、词源、对应概念、画面理解；
- 管理层：导入、导出、洗牌、偏好、重置、词表维护。

理解层按需出现，管理层不进入连续学习画面。

### 5. 自定义词表是用户资产

导入、保存、恢复和导出是产品核心价值，不得因为追求“极简”而被削弱。

### 6. 所有系统行为都要可逆、可解释

“从词表移除”“暂时不出现”“等待返场”是三种不同含义，必须有不同文案与恢复路径。

### 7. 概念优先于翻译

释义的目标不是尽快建立“英文单词 = 中文词语”的一对一反射，而是帮助用户先接触单词所指向的概念。当前阶段以足够简单、不会制造理解负担的英英释义作为主要手段，中文保留为最后的快速定位和语义校准层。未来再试验用 AI 寻找或生成的核心画面承担第一释义信息。

## 三、非目标

3.0 暂不追求：

- 通用英语课程或大型公共词库；
- 排行榜、成就、社交和重统计仪表盘；
- 以复杂算法本身作为卖点；
- 完整替代 Anki 式长期、跨月间隔重复；
- 账户、云同步或必须安装的原生 App；
- 在学习时展示所有已有功能。

## 四、核心产品闭环

### 推荐主循环

**准备/恢复词表 → 辨识 → 轮末过渡 → 合格词拼写 → 下一轮辨识或明确完成**

#### 1. 准备/恢复词表

- 有本地词表时，直接恢复上次位置；
- 没有词表或主动更换时，进入独立的“准备词表”流程；
- 文件导入、粘贴导入和 AI 生成后的导入，都以同一个成功状态收口；
- 导入成功后立即提供“保存副本”，不要求用户理解 JSON 文件操作细节。

#### 2. 辨识

- 未翻开：只需辨认单词；
- 翻开：确认词性和核心含义；
- `Enter` 表示“我认出来了并继续”；
- `N` 表示“我没有认出来”；
- 系统用这些低摩擦证据判断该词继续辨识还是具备拼写资格。

#### 3. 轮末过渡

轮末不再固定问“继续刷词还是随手拼”。它先说明本轮结果，再给一个明确的默认下一步。

- 合格词形成 3–5 个小批次：默认进入拼写；
- 合格词不足 3 个且仍有未稳定词：保留已有资格并继续辨识，等待形成小批次；
- 只剩 1–2 个合格词且已无法继续积累：放行尾批，避免流程卡住；
- 没有到期词：进入明确完成态，说明原因并提供自由复习入口；
- 用户始终可以用次级动作改选，但无需每轮重新做决定。

#### 4. 拼写

- 只练已经具备辨识基础的词；
- 第一次提交用于判断学习状态；
- 拼错的词回到“继续辨识”；
- 拼对的词进入“延后复习”；
- 改正拼写是练习行为，不覆盖第一次结果。

#### 5. 返场

返场继续存在，但成为后台策略。用户只需要理解三种状态：

- 继续辨识；
- 可以拼写；
- 之后再复习。

“study hidden / spell hidden / synced / due round”等内部概念不进入日常界面。

## 五、关键产品决策

### 决策 1：熟悉判断是否继续作为可选模式

| 方案 | 优点 | 缺点 |
| --- | --- | --- |
| A. 保留当前简单模式，熟悉判断默认关闭 | 最接近 2.0；完全没有评分压力 | 系统没有证据，无法自动筛选拼写词 |
| B. 把轻量辨识判断纳入默认主循环 | 可以自动分流；`Enter` 仍是主操作 | 需要保留 `N`，并解释系统为何分流 |
| C. 根据停留时间等行为暗中猜测 | 用户无需做任何判断 | 不可靠、不透明，容易把看过答案误判为会了 |

**推荐 B。**“两轮熟悉返场”不再作为日常开关，而是主循环背后的基础学习策略。它可以保持轻量，不必恢复成两颗长期显眼的大按钮。

### 决策 2：辨识结束后如何进入下一阶段

| 方案 | 优点 | 缺点 |
| --- | --- | --- |
| A. 每轮让用户在辨识和拼写之间选择 | 自由度高 | 每轮打断节奏；当前问题继续存在 |
| B. 固定把整份词表送去拼写 | 逻辑简单 | 大量明显不会的词进入拼写，挫败且低效 |
| C. 系统按合格词自动路由，用户可改选 | 连续按 `Enter` 即可；拼写更有效 | 必须把系统理由说清楚 |

**推荐 C。**默认路线由系统决定，次级键位仅用于手动改选。

### 决策 3：词进入拼写的初始门槛

| 方案 | 优点 | 缺点 |
| --- | --- | --- |
| 一次辨识正确 | 更快进入拼写 | 容易把刚看过答案的短期熟悉误当掌握 |
| 两个不同轮次辨识正确 | 与现有机制兼容；证据更稳定 | 进入拼写稍慢 |

**已确认实验性采用两个不同轮次正确作为 v0.1 规则。**下一份真实作业中验证；如果进入拼写明显过慢，则退回一次正确。

### 决策 4：深入理解功能放在哪里

| 方案 | 优点 | 缺点 |
| --- | --- | --- |
| 顶部常驻，与 Import / Export 同级 | 随时可见 | 与准备词表功能职责不同；点击后缺少上下文 |
| 只放 Guidebook | 主界面安静 | 遇到难词时路径太长 |
| 放在当前单词的按需理解入口 | 与真实触发场景一致；可自动带上当前词 | 需要设计清楚二级入口和复制反馈 |

**推荐第三种。**动作结果应是“复制当前词的深度理解请求”，并提示用户下一步把内容粘贴到任意 AI，而不是只说“已复制提示词”。

### 已由 User Flow 批注确认的配套规则

- 新词表解析成功后直接替换，不增加事前确认；替换后提供 Undo。
- 拼写候选先积累成 3–5 个的小批次；若已无法继续积累，最后 1–2 个直接放行。
- 当前无待办时，`Enter` 结束本次并停留在完成态；自由抽查由用户主动进入。
- 拼写首次错误后必须正确重打一次，但不覆盖首次错误结果。
- `Esc` 或关闭网页会暂停并保存当前拼写批次，不视为放弃。
- Remove 立即执行并提供 Undo，不增加确认弹窗。
- 首次无词表时的首屏路径仍待低保真 A/B 对比后确认。

详细分支见 [User Flow 决策总表](flashvocab-3-user-flow.md#decision-summary)，每个编号可继续跳回对应规则。

## 六、信息架构与功能分层

### 学习主层：始终可用

- 翻开、继续、没认出；
- 当前词与核心释义；
- 单一轮内进度；
- 自动发音；
- 拼写输入与结果。

### 上下文辅助层：卡住时出现

- 手动发音；
- 例句；
- 词源、词根、对应概念；
- 当前词的“词根·感觉·画面”；
- 复制当前单词。

### 工具与设置层：主动打开

- Import、保存副本、Export；
- Shuffle；
- 自动发音偏好；
- 理解内容显示偏好；
- 学习状态与熟悉词；
- 使用说明；
- 重置学习进度；
- 恢复内置词表或更换词表。

### 从学习主界面移出

- 七个常驻文字按钮；
- 三个常驻开关；
- 熟悉池长列表；
- 辨识轮数、拼写轮数、两套熟悉数字；
- 顶部深度提示词按钮；
- 与当前模式无关的 disabled 控件。

## 八、UI/UX 方向

### 1. 阅读动线

当前问题来自英文与中文被合并为一行：英文过长时，中文会落在右侧或下一行，视线形成不稳定的 Z 字跳转。

当前阶段建议固定为：

1. 单词保持固定视觉锚点；
2. 词性保持为轻量辅助信息；
3. 足够简单的英英释义作为第一释义行和主要阅读对象；
4. 中文释义独占最后一层，降低视觉权重，只用于快速定位大致含义或校准理解；
5. 例句默认只展示一条或折叠；
6. 词源、对应概念和深度画面理解进入“理解层”。

翻开时内容出现，但单词和释义起点不跳位。英英释义的措辞必须优先做 easy 化：它不应为了“准确得像词典”而引入更多陌生词，迫使用户回头依赖中文。

### 2. 未来试验：画面作为第一释义

未来计划试验：用 AI 寻找或生成能够表达单词原型场景、核心动作或底层感觉的画面，让画面成为翻开后视觉上最先被感知的释义信息。其后的信息顺序为：

1. 核心画面；
2. 简明英英释义；
3. 中文快速定位与校准。

这个方向的目标，是减少从英文立即直译成中文的习惯，逐步建立“英文 → 概念/场景”的直接联系。中文不会被删除，因为抽象词、多义词和临考快速确认仍然需要它。

图片目前只属于未来试验，不是 3.0 初始版本的必要条件。正式采用前需要验证：

- 画面是否对应本次词表实际考查的义项，而不是只表现另一个常见义项；
- 抽象词能否得到可靠且不过度隐喻化的画面；
- AI 画面是否引入错误细节或误导性联想；
- 不同单词的图片风格、信息密度和读取速度是否一致；
- 图片获取或生成是否增加准备时间，违背“少、轻、快”的原则。

在这些问题得到验证前，产品优先把简明英英释义做好。

### 3. 静默模式

开始连续使用键盘后，标题、顶部入口、管理按钮和设置淡出为低注意力状态。它们在以下情况恢复：

- 指针再次移动；
- 触摸工具区域；
- 按 `Tab` 或 `Esc`；
- 当前流程需要它们。

静默模式只改变视觉权重，不移动卡片，也不让功能从辅助技术中消失。移动端不应照搬桌面的自动隐藏。

### 4. 键位提示

- 使用真实键帽形状表达 `Enter`、`Space`、`N`、`Esc`；
- 主键高对比，替代键低对比；
- 键位在不同状态保持相近位置；
- 文案解释动作结果，如“开始拼写”，不重复朗读键名；
- 一个状态只允许一个视觉主动作。

### 5. 图形化状态

- 两轮辨识状态用两个小点或两格胶囊表达；
- 返场用小回环标记，同时保留文字或辅助技术标签；
- 本轮位置只出现一次；
- 不再同时显示卡内进度、底栏进度和熟悉池数字；
- 颜色不能成为唯一状态信号。

### 6. 动效

- 只用于内容进入、阶段连续性、完成和错误反馈；
- 单个视图最多保留 1–2 个关键动效；
- 进入使用 ease-out，退出使用 ease-in；
- 避免持续漂浮或所有元素同时变化；
- 必须支持减少动态效果偏好。

## 九、边界状态

后续视觉稿必须覆盖：

- 第一轮没有任何拼写候选；
- 拼写候选只有 1 个；
- 所有词都进入延后复习，但当前没有到期词；
- 有到期词但本轮只选中一部分；
- 拼写错误后重试并改正；
- 拼写中按 `Esc`；
- 中断后再次打开；
- 导入新词表会替换当前词表；
- 文件导入与粘贴导入的成功收口；
- 从当前词表移除、撤销、重置学习进度、恢复内置词表；
- 移除最后一个词。

“没有词”不能只用页面顶部的一行小提示解释。它必须是主画面中的明确过渡或完成状态。

## 十、可访问性验收原则

- 标准控件可通过 `Tab` 到达，并有清晰焦点状态；
- 全局快捷键不应以取消标准键盘导航为代价；
- 点击复制的单词需要等价的按钮语义和键盘操作；
- 不把整张卡片的大段内容作为频繁播报区域；
- 只让错误、成功、空队列和关键阶段变化进行简短播报；
- 键帽提示、熟悉点和返场标记都提供文字含义；
- 浅色提示文字和半透明背景需要实测对比度；
- 缩放至 200% 时，信息按逻辑顺序重排，不横向滚动；
- 动效尊重减少动态效果设置。

## 十一、成功信号

3.0 是否成功，不先看“新增了多少功能”，而看以下行为：

- 用户收到一份新词表后，可在一次短操作内开始第一张，并把词表保留到下次；
- 连续学习 10–15 分钟时，主路径不需要鼠标，也不需要停下来阅读 Enter / Space 的分支说明；
- 任意阶段只有一个明确主动作，用户能在 3 秒内说清按 `Enter` 会发生什么；
- 多数词可以通过足够简单的英英释义完成理解，中文只在快速定位或校准时被使用；深层内容只在卡住时被主动展开；
- 进入拼写的词中，“完全不知道是什么”的比例明显低于整表直接拼写；
- 用户不会把“无返场词”“暂时隐藏”或自动跳转理解成 bug；
- 词表替换、删除和学习进度重置的结果不会被混淆。

## 十二、仍需验证的假设

1. 已实验性采用两个不同轮次正确：验证是否让进入拼写明显过慢；
2. 已实验性采用 3–5 个拼写小批次：验证批量感是否更自然，以及是否推迟验证过久；
3. `N` 是否足够低摩擦，移动端需要什么等价动作；
4. 返场继续按“轮”计算，是否比按真实时间更符合碎片使用；
5. 例句默认展示一条还是全部折叠；
6. 静默模式应在首次键盘操作后立即触发，还是在 1–2 秒静止后触发；
7. 画面优先是否真的减少中文直译，并提高对单词核心含义的理解；
8. 哪些词适合画面表达，以及图片应由 AI 搜索、生成还是混合获得。

这些问题应先通过低保真状态稿和实际使用验证，不在代码实现前拍脑袋定死。

## 十三、下一阶段设计工作面

下一阶段只需要先画清六类关键画面：

1. 辨识未翻；
2. 辨识已翻；
3. 辨识评分/返场；
4. 轮末过渡的五种结果；
5. 拼写输入、正确和错误；
6. 准备词表与工具抽屉。

准备词表需要额外画两种首屏低保真方案：A 直接进入内置词表；B 准备词表为主、内置示例为次。只比较实际进入感受，用于确认 User Flow D1。

这六类画面确认后，再定义四个共用组件：静默模式、键帽、两点熟悉度、工具抽屉。辨识已翻和拼写输入先按“简明英英释义优先、中文最后校准”设计；画面优先另做未来试验稿，不阻塞当前方案。视觉配色延续 2.5 的沙色、珊瑚与青绿基线；2026-09-08 增补的暗色模式使用暖炭黑、柔和青绿和降饱和珊瑚一一对应原层级，默认跟随系统，并允许在工具抽屉固定亮色或暗色。
